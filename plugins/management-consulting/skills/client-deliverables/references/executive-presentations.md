# Executive Presentations

Load this when the deliverable is a deck. The core SKILL.md carries the shared logic (SCR storylining, the pyramid, action titles, audience adaptation, exhibit selection, writing standards). This file carries deck-specific craft: structure, slide anatomy and exhibit recipes, board dynamics, pre-wiring, backup, Q&A, live handling, and the one-page memo.

## Define the Core Message First

Before opening any slide tool, write three things:

1. **The answer in one sentence**: "We should enter Germany by acquiring [Target] for EUR 120M."
2. **The three supporting arguments**: why now, why this target, why acquisition over organic.
3. **The evidence for each**: market data, target financials, comparable transactions.

If you cannot write these clearly, you are not ready to build slides. The blank-slide reflex is the enemy here.

## Deck Structure

| Slide Type | Purpose | Key Elements |
|---|---|---|
| Title | Set expectation | Punchy title (max 6 words), subtitle with the key message, presenter, date |
| Executive Summary | Full message for time-pressed readers | 3-5 bullets covering the complete recommendation, bottom line up front |
| Context / Situation | Establish common ground | Facts the audience agrees with, current-state data |
| Problem / Complication | Create urgency | Impact metric, trend visual, quantified cost of inaction |
| Analysis | Show the thinking | One framework visual (2x2, waterfall), the insight in one sentence |
| Recommendation | Present the answer | The recommendation in one line, why now / why this, quantified impact |
| Financial Impact | Prove the value | Benefits, costs, net value, a waterfall or bridge, key assumptions and sensitivity |
| Roadmap / Next Steps | Call to action | Phased timeline with actions, owners, dates, the immediate first move |

## Slide Anatomy

```
+-------------------------------------------+
| ACTION TITLE (complete sentence)          |  <- The slide's takeaway
+-------------------------------------------+
|                                           |
|   [Exhibit: chart, table, framework]      |  <- Visual evidence
|                                           |
|                                           |
| Source: [data source, date]               |  <- Attribution
+-------------------------------------------+
```

The action title is what separates a consulting slide from everything else. Write it as a complete sentence stating the takeaway. The body is exhibit-driven: charts, tables, and frameworks dominate, and paragraphs do not. One focused exhibit is ideal. Two side by side work only when they jointly support the one action title.

Run the **"so what"** test on every slide. So what (why should they care)? Says who (what is the source)? What if (what are the implications)? If you cannot answer "so what" in one sentence, cut or rebuild the slide.

## Exhibit Recipes

Exhibit selection lives in SKILL.md. Construction detail lives here.

**Tornado chart** (which variable matters most): variables listed vertically, NPV impact range horizontal, ordered by swing magnitude. The top 2-3 bars are where management attention belongs.

**Waterfall / bridge** (revenue to EBITDA, cost drivers, base to target): each bar is one driver, colored consistently for increases vs. decreases, with the net change labeled at both ends. One bridge per slide.

**Scenario table** (overall risk profile): base, upside, downside as columns; assumptions, returns (NPV, IRR, payback), and probability weighting as rows. State the break-even in the title or a callout. Probability weightings without hard data are directional estimates; label them.

**2x2 framework** (positioning, prioritization): name both axes with a direction of "good," place items as dots, and annotate the quadrant that carries your recommendation. Do not leave the reader to infer which quadrant wins.

Presentation exhibit rules: one chart per slide making one point; annotate the insight directly on the chart; no pie over 4-5 slices; no table over five rows in a live deck (push the detail to backup).

## Presentation vs. Leave-Behind

Density differs by use. Decide which you are building before you start.

| Dimension | Presentation Deck | Leave-Behind / Read-Ahead |
|---|---|---|
| Primary audience | People in the room | People reading alone, later |
| Font size | 30pt minimum | 18pt minimum |
| Content density | One point per slide | 2-3 points per page acceptable |
| Exhibits | One per slide, annotated | Supporting detail allowed |
| Action titles | Short, punchy | Longer, more descriptive |
| Appendix | Separate backup | Inline or appended |
| Typical length | 8-12 slides + backup | 15-30 pages |
| Goal | Drive a decision in the room | Survive forwarding to people who were not there |

A deck that gets forwarded as a read-ahead usually fails at both jobs. If one artifact must serve both, add a 1-page standalone executive summary and move supporting detail into clearly labeled appendix sections.

## 10-Slide Report Summary

When a report also needs a board or executive presentation, build a 10-slide summary. This is not "the report on slides." It is the argument restructured for a spoken format.

| Slide | Content | Notes |
|---|---|---|
| 1. Title | Report title, date, classification | Match the report cover |
| 2. Executive summary | 3-5 bullets, recommendation with impact numbers | Someone who sees only this gets the full message |
| 3. Situation | Context the audience agrees with | 2-3 data points, not a wall of text |
| 4. Complication | What changed or is at risk | Quantify the cost of inaction |
| 5. Key finding #1 | Strongest finding | One chart or framework, action headline |
| 6. Key finding #2 | Second finding | One chart or framework, action headline |
| 7. Key finding #3 | Third finding (if needed) | Merge with #6 if two suffice |
| 8. Recommendation | What to do, quantified impact | Options table if multiple paths |
| 9. Scenario / sensitivity | Base, upside, downside with triggers | Tornado or scenario table |
| 10. Next steps | Actions, owners, dates | First action achievable this week |

## Board Decks

Boards have distinct dynamics. Directors carry fiduciary duty, have little time, and see dozens of proposals.

Frame every recommendation in terms of shareholder value, risk, or strategic positioning. Boards think in fiduciary terms, not operational efficiency. If the proposal touches audit, compensation, or risk committees, address their specific mandate: an audit committee wants control frameworks, a risk committee wants quantified exposure, a compensation committee wants incentives aligned to outcomes.

Boards want to see the investment relative to the total capital budget (context, not just the number), the downside scenario and the plan for it, the competitive cost of acting vs. not acting, management's confidence and its basis, and a clear decision request (approve, approve with conditions, or defer). Boards do not want operational detail they cannot evaluate (send it to backup), options with no recommendation (they hired management to decide), or surprises (pre-wire first).

## Pre-Wiring

Pre-wiring is socializing the recommendation with influential stakeholders before the formal meeting. It kills surprises, surfaces objections you can absorb into the deck, and turns potential opponents into non-blockers.

Pre-wire the decision-maker, anyone with veto power, known skeptics, and anyone whose public reaction sways the room. Ask for 15-20 minutes 1:1: "I want to make sure this lands. Can I walk you through the key points?" Share the recommendation and 2-3 data points, not the full deck. Ask for their reaction and listen more than you pitch. Fold legitimate objections into the deck. If someone disagrees fundamentally, you now know before the meeting and can adjust scope, framing, or the ask.

Timing: 2-5 days out. Too early and context shifts; too late and you cannot adjust. Pre-wiring is not lobbying for a predetermined outcome. If it reveals the recommendation is wrong, change the recommendation.

## Backup Slides

Every deck ships with backup ready for Q&A. Build it before you need it. Standard categories: detailed methodology and assumptions, the full financial model with sensitivity tables, competitive benchmarking, the risk register with mitigations, rejected alternatives, and the implementation timeline at workstream level.

Format backup with the same action-title discipline as the main deck. Label each clearly ("BACKUP: Detailed NPV Assumptions") and number them separately (B1, B2, B3) so you can jump to one on demand.

## Storytelling Techniques

| Element | Technique | Example |
|---|---|---|
| Start strong | Provocative question or data point | "Every quarter we wait costs us $X million." |
| Create tension | Cost of inaction | "The window closes in two quarters." |
| Show the journey | A concrete finding | "We met 50 customers and heard the same thing." |
| Build to climax | Layer insights | "First we found X, then Y, which led to Z." |
| End with action | A clear decision request | "We recommend you approve Phase 1 by Friday." |

## Flex Structure

No presentation survives first contact with the audience. Build so you can adapt live.

Before the meeting, know which slides are load-bearing (must show) and which are supporting (can skip), and mark them in your notes. A typical 12-slide deck has 5-6 must-show slides.

Read the room. If they are nodding through context, skip ahead: "You are aligned on the context, so let me jump to the analysis." If they are stuck on a point, stop advancing; moving to slide 4 while the room is still on slide 3 wastes slides 4-12. If a question jumps to a later slide, go there rather than saying "I'll get to that." If energy drops in detailed analysis, cut to the recommendation and work backward.

Structural enablers: numbered backup slides for fast navigation, section dividers so you can skip a section cleanly, and three rehearsed paths through the deck (full, abbreviated, and cut-to-the-chase: summary plus recommendation plus next steps).

## Handling Live Edits

Clients will ask for slide changes mid-meeting. This is normal. Edit live for wording changes that reflect genuine alignment, a caveat the room agrees on, or a number someone improves in the moment. Do not edit live for structural changes that need the argument rethought, for one person's preference dressed as consensus, or for anything over 60 seconds of work.

Handle it cleanly: "Good point, let me capture that." Make the quick edit, or note it and confirm "I'll update and circulate by [time]." If slides are projected, have a second person edit on a laptop while you keep presenting. Read back the revised language: "So it now reads [X]. Does that capture it?" Send the updated deck within 24 hours with changes highlighted.

## Handling Q&A

Prepare an anticipation table for every presentation:

| Anticipated Question | Why It Is Hard | Best Response | Fallback |
|---|---|---|---|
| "Why not option B?" | They may prefer it | Data showing A outperforms | "Happy to model both." |
| "What is the downside?" | Forces you to own risk | Quantified risk with mitigation | "We stress-tested three scenarios." |

Response pattern: listen completely without interrupting; confirm the question ("So what you are asking is..."); answer directly, leading with the answer; confirm resolution ("Does that cover it?"). When you do not know, say so: "I do not have that with me. I'll follow up by [date]." Credibility comes from honesty, not from bluffing.

When a full deck is overkill:

```
# Memo: [Recommendation Title]

## Recommendation
[What you recommend, in one clear statement]

## Problem
[The challenge or opportunity this addresses]

## Analysis
1. [Finding 1 with evidence]
2. [Finding 2 with evidence]
3. [Finding 3 with evidence]

## Value
- [Benefit 1, quantified]
- [Benefit 2, quantified]

## Implementation
- Timeline: [Duration]
- Key milestones: [Milestones]
- Investment required: [Amount]

## Risks and Mitigations
| Risk | Mitigation |
|------|-----------|
| [Risk 1] | [Mitigation] |
| [Risk 2] | [Mitigation] |

## Decision Needed
[What you need from the decision-maker, by when]

## Next Steps
1. [Immediate action, owner, date]
2. [Follow-up action, owner, date]
```

## Design Principles

Use brand colors consistently (client's or firm's, per context). Limit to 3-4 colors per slide, and use color to highlight rather than decorate. Keep high contrast, consistent fonts and sizes, and color-blind-friendly palettes. White space is a feature, not waste.

## Behavioral Principles

- **Lead with the answer, always.** State the recommendation in the first 30 seconds, then earn the right to explain.
- **Every slide passes the "so what" test.** If you cannot say why the audience cares in one sentence, cut it.
- **Quantify or drop the claim.** Attach a number, a source, or a date to every assertion.
- **Design for the skeptic.** Assume someone challenges your logic, and build the pyramid so each level holds on its own.
- **Less content, more conviction.** A 7-slide deck delivered with authority beats a 30-slide deck that hedges. Cut hard and own what stays.
- **Design for the screen first** when the audience is part in-room and part remote.
